# technical-docs-ux

技術仕様書・設計書の情報配置と参照経路を整えるCodexスキル。必要な情報を保ちながら、結論・要点がすぐ分かり、初担当者も経験者も必要な答えにたどれる文書を作る。

## できること

- 読者が理解・判断したいことから、説明順と概要・詳細の分担を選ぶ。
- 途中の節から読んでも、前提・操作条件・次の行動へたどれるようにする。
- 図・表・本文を使い分け、責務・順序・条件を誤解させずに伝える。

新規作成や構成の見直しに使う。構成が決まった追記や、値・表現だけの修正は適用対象外。資料にない仕様・保証・選択理由は補わず、情報配置の問題と資料不足を区別する。

## 導入

Codexでskill-installerを使い、次のように依頼する。

```text
$skill-installer https://github.com/tug-hour/technical-docs-ux-skill/tree/main/technical-docs-ux
```

導入対象は[technical-docs-ux/](technical-docs-ux/SKILL.md)だけ。指示本体のSKILL.md、表示情報のagents/openai.yaml、LICENSEの3ファイルを含む。実行スクリプト・追加依存・自動更新はない。既に導入済みの場合は原本との差分を確認して更新する。

## 使い方

```text
$technical-docs-ux この設計書を、初めて担当する技術者が全体像を理解でき、
経験者も必要な仕様をすぐ参照できるように改善してください。
```

新規作成では、文書の用途・読者と、仕様の根拠となる資料を渡す。導入後は対象の依頼で自動選択の候補になるが、明示指定することもできる。文書数・章立て・図・独立読者テストを一律には要求しない。

## 問い合わせ・変更提案

不具合や改善案は[Issues](https://github.com/tug-hour/technical-docs-ux-skill/issues)へ、対象の版・文書の用途・困った箇所を添えて報告する。例文は公開できる最小限のものを使い、認証情報や非公開の業務文書を添付しない。変更提案はPRで受け付ける。
